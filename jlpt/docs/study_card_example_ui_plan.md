# 학습 카드 예문 화면 변경 계획

## 1. 범위

### 목표

학습 카드에서 일본어 예문은 처음부터 보여 주고, 예문 한국어와 전체 히라가나는 기존 `한국어`·`히라가나` 버튼으로 공개한다.

선행 조건:

- `n1_example_data_plan.md`의 데이터·타입·SQLite 작업 완료

포함 범위:

- 학습 카드의 예문 위치와 공개 동작 변경
- 카드가 바뀔 때 공개 상태 초기화
- 작은 화면에서 문장이 자연스럽게 줄바꿈되도록 조정

제외 범위:

- 별도 `예문 보기` 버튼
- 예문 편집·즐겨찾기·음성 재생
- 회독 큐, 타이머, 세션 저장 방식 변경
- 홈·프리셋·기록 모달 화면 변경

## 2. 확정된 화면 흐름

### 최초 표시

```text
[단어]
[품사]
[일본어 예문]
[한국어 공개 영역: 빈 상태]
[히라가나 공개 영역: 빈 상태]
[한국어] [히라가나]
[공부하겠음] [알고있음]
```

일본어 예문은 `exampleJp`가 있을 때 항상 표시한다. 별도 공개 상태를 만들지 않는다.

예문 블록에는 `exampleJp`만 렌더링한다. 현재 예문 블록에서 항상 렌더링하는 `exampleKo`는 제거하고 아래 `한국어` 공개 영역으로 옮긴다.

**선택 이유:** 일본어 문맥은 의미 회상을 돕는 단서이고, 이를 다시 숨기는 버튼은 학습 효과보다 조작 횟수만 늘린다.

### `한국어` 버튼

- 누르면 단어의 `meaningKo`와 예문의 `exampleKo`를 함께 표시한다.
- 공개 영역에서 단어 뜻은 기본 텍스트, 예문 번역은 그 아래 보조 텍스트로 구분한다.
- 다시 누르면 둘을 함께 숨긴다.
- `exampleKo`가 없으면 단어 뜻만 표시한다.
- `showMeaning`이 `false`일 때 `exampleKo`는 화면과 화면 판독기 어디에도 노출하지 않는다.

### `히라가나` 버튼

- 누르면 단어의 `readingHiragana`와 예문의 `exampleReadingHiragana`를 함께 표시한다.
- 공개 영역에서 단어 읽기는 기본 텍스트, 예문 읽기는 그 아래 보조 텍스트로 구분한다.
- 다시 누르면 둘을 함께 숨긴다.
- 예문 읽기가 없으면 단어 읽기만 표시한다.

기존 `showMeaning`, `showReading` 두 상태를 그대로 사용한다.

**선택 이유:** 단어와 예문마다 별도 공개 상태를 두면 사용자가 네 가지 상태를 관리해야 한다. 기존 두 버튼이 같은 언어 정보를 한 번에 공개하는 편이 명확하다.

### 카드 전환과 종료

| 조건 또는 동작 | 처리 |
| --- | --- |
| `공부하겠음`·`알고있음`으로 다음 카드 이동 | 새 카드의 한국어·히라가나를 모두 숨김 |
| 새 패스 시작·재셔플 | 첫 카드의 한국어·히라가나를 모두 숨김 |
| `나가기` 후 세션 재진입 | 한국어·히라가나를 모두 숨긴 상태로 시작 |
| 예문 데이터 없음 | 예문 영역만 렌더링하지 않고 기존 단어 학습 유지 |
| 긴 예문 | 카드 폭 안에서 줄바꿈하고 화면 전체를 스크롤 |
| 데이터·네트워크 오류 | 새 오류 흐름 없음; 기존 초기화·세션 오류 처리 유지 |

## 3. 상태 및 데이터 계약

```ts
const [showMeaning, setShowMeaning] = useState(false);
const [showReading, setShowReading] = useState(false);
```

- 소유자: `AppShell` 로컬 상태
- 생존 범위: 현재 열려 있는 학습 카드
- persistence: 저장하지 않음
- 초기화: 현재 `wordId` 또는 `currentPassNo`가 바뀌는 기존 effect

Zustand, SQLite, 세션 큐에는 공개 상태를 추가하지 않는다.

**선택 이유:** 공개 여부는 학습 진행 데이터가 아닌 일시적인 화면 상태다. 저장하면 재진입 시 정답이 열린 채 보일 수 있다.

화면이 받는 예문 데이터:

```ts
type CurrentCard = {
  exampleJp: string | null;
  exampleReadingHiragana: string | null;
  exampleKo: string | null;
};
```

API 호출, 로딩 상태, 재시도 정책은 추가하지 않는다.

## 4. 파일별 작업

### 수정

| 파일 | 책임 |
| --- | --- |
| `app/App.tsx` | 예문을 단어 아래로 이동하고 기존 두 공개 영역에 번역·읽기 연결 |

`App.tsx` 안에서 현재 JSX와 `StyleSheet`만 수정한다. 단일 화면에서만 쓰는 예문 컴포넌트나 훅을 새 파일로 분리하지 않는다.

### 변경하지 않음

| 파일 | 이유 |
| --- | --- |
| `app/src/store/useAppStore.ts` | 공개 상태와 예문 표현은 화면 책임임 |
| `app/src/features/study/engine.ts`의 큐 액션 | 카드 선택·완료 규칙은 바뀌지 않음 |
| `app/src/db/*` | 데이터 계획에서 완료해야 하는 선행 작업임 |

## 5. 구현 제한과 접근성

- 예문 블록은 현재 액션 버튼 아래가 아니라 단어·품사 바로 아래에 둔다.
- 일본어 예문과 공개된 보조 문장은 카드 폭에 맞춰 줄바꿈한다.
- 숨긴 한국어·히라가나는 `opacity`로 가리지 말고 조건부 렌더링하여 화면 판독기에 노출하지 않는다.
- 두 공개 버튼에 `accessibilityRole="button"`과 각각 `accessibilityState={{ expanded: showMeaning }}`, `accessibilityState={{ expanded: showReading }}`를 제공한다.
- 공개 전 답을 의미하는 자리표시자 텍스트는 표시하지 않는다.
- 기존 색상, 간격, 버튼 라벨을 재사용하고 새 디자인 시스템이나 의존성을 추가하지 않는다.
- `exampleJp`가 없는 카드에서도 `한국어`, `히라가나`, 두 학습 액션은 기존대로 동작해야 한다.

## 6. 검증

```bash
cd app && npm exec tsc -- --noEmit
```

- [ ] 카드 진입 직후 일본어 예문만 보인다.
- [ ] `exampleKo`는 예문 블록에서 항상 표시되지 않는다.
- [ ] `한국어` 버튼이 단어 뜻과 예문 번역을 함께 열고 닫는다.
- [ ] `히라가나` 버튼이 단어 읽기와 예문 전체 읽기를 함께 열고 닫는다.
- [ ] 한 버튼을 눌러도 다른 버튼의 공개 상태는 바뀌지 않는다.
- [ ] 다음 카드, 새 패스, 세션 재진입 시 두 공개 상태가 초기화된다.
- [ ] `공부하겠음`·`알고있음`의 큐 결과와 타이머가 기존과 같다.
- [ ] 예문 누락 카드에서도 화면과 학습 액션이 정상 동작한다.
- [ ] 긴 예문을 iPhone 소형 화면과 Android 화면에서 읽고 스크롤할 수 있다.
- [ ] VoiceOver·TalkBack에서 숨긴 답을 읽지 않고 버튼 상태를 구분할 수 있다.
